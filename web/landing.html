Stop conflicts where they start.

Most broken merges are born while agents write, not at review. When several agents edit the same codebase at once, they overwrite each other or produce conflicting branches that someone has to untangle later. Lanes prevents that at the source.

Without Lanes

  1. Agent A and agent B both edit TypeCollector.cs.
  2. Both open pull requests against the same lines.
  3. The second merge conflicts, or silently undoes the first.
  4. A person finds out at review, or in production.

With Lanes

  1. Before every edit, the agent's hook asks the Lanes server for a lease on that file.
  2. Agent B's request waits in line, first come first served, while A holds the file.
  3. When A is done, B gets the lease and edits on top of A's change.
  4. Every commit carries a Lanes-Agent line, so Vouch knows which agent wrote what.

The planted-bug benchmark

We wrote 10 realistic agent changes to our demo repository, each hiding one known bug, and ran Vouch exactly as in production, without the answer key. Stopped means the bug was blocked, or its line was on the reading list in front of a person.

7/10Guardrail and Checkpoint alone. Missed: a wrong boundary with a test written to match, a wrong VAT formula with a matching test, and a silent rate change on a tested line.
8/10With mutation proof, first version: breaking the code exposed the boundary test that checked nothing.
10/10Mutating every constant on a line separately, as standard mutation tools do: the silent rate change and the VAT line went to a person too.

Honest notes: 10 bugs we wrote ourselves, in a small repository, is a small sample. The VAT line reached a reviewer because its rounding was untested, not because the formula was detected: a wrong value with a test that agrees is still the hardest case.

The AI never decides what you skip.

The AI proposes. Plain code decides. A person signs. These are the exact rules, the same on every run.

Guardrail

Run the existing tests on the base and on the branch. Passed before and failed after: blocked. Tests could not run: read everything.

Checkpoint

Each AI claim must pass 4 checks: the cited lines were added by this change, the quote is in the issue word for word, the named test exists, and it passed. All 4: proven. One of the first 3 fails: disputed. Test not passed: unproven. The AI's confidence score is never used.

Reading list

Start with every meaningful added line. Remove only lines cited by a proven claim. Put back anything that touches public API, analyzer warnings, unsafe code or dependencies, always.

Mutation proof

Vouch breaks every proven line on purpose (> to >=, + to -, a constant changed) and runs the tests again. If no test fails, the tests do not pin that line down: back on the reading list.

Sign-off

Refused by code unless every step is approved by someone, nothing regressed, and the owner wrote the risk they accept. Then the decision goes to GitHub.

Fail closed

If any part does not finish (tests, AI, a check), nothing is folded away. You see more code, never less.

Known limit: mutation proof shows a test pins a line down, not that it expects the right value. If an agent writes a wrong function and a test that agrees with it, both are consistent. The benchmark above measures exactly this.

Questions reviewers ask

Isn't this just AI deciding what humans review?

No. The AI only proposes a map of the change. Code decides what folds: the cited lines must exist, the named test must have passed on the branch, and no risk rule may apply. The AI's confidence is never used. Next, we will also require coverage proof that the named test actually runs those lines. A named person signs every merge.

What if the tests are weak?

Then less folds away. Vouch breaks the proven code on purpose and re-runs the tests: if they do not notice, the line stays on your reading list. Risky areas like public API are always shown, even when every test passes.

Who built Lanes?

We did. Lanes is built in house, like the rest of Vouch. The source is on GitHub.

Do I need Lanes to use Vouch?

No. Without Lanes, every change counts as written by an unknown agent, so nothing is trusted by default. With Lanes, agents work in parallel without collisions and trust is earned per agent and per area of the code.

Why Aiven?

A review is shared and live. Postgres keeps the record, Kafka lets other tools react to each vote and sign-off, and Valkey holds who is reviewing right now. Aiven runs all three as managed services.

Which languages does it support?

Guardrail runs your existing tests with each language's own tool: .NET, Python (pytest), JavaScript and TypeScript (Vitest, Jest or node --test), Go, Java and Kotlin (Maven or Gradle) and Rust (cargo). .NET, Python and JavaScript are tested end to end today. Repositories are on GitHub.
