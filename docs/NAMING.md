# Naming and public landscape

## Chosen name

**Vouch** is the best working name. It is short, memorable, and says exactly what the human does: vouch for a change after seeing the evidence.

Suggested one-liner:

> Vouch turns AI-written pull requests into evidence-backed decisions a human can sign.

## Backups

- Proofline - clear evidence, slightly more abstract.
- Earned - matches the trust mechanic, but is broad.
- Readlist - describes the output, not the product.
- MergeProof - very clear, less brandable.
- Trustrail - strong metaphor, slightly security-tool sounding.

Avoid `TietoTrust`, `JunctionTrust`, and `AIReviewer`: they are too tied to the event or too generic.

## Public search completed

Searches covered: `Tieto Junction`, `tieto-junction`, `Tieto HackJunction`, `Junction 2026 Tieto`, `hackjunction tieto`, `Aiven Junction 2026`, `earned trust`, `MessagePack Junction`, and `junction26`.

Relevant public results:

- `JesseSaarinen/tieto-trust-review` - a strong CLI/reference implementation focused on evidence packs, reading lists, and a second-model breaker.
- `te-industry-tech-office/junction26-messagepack-csharp` - Tieto's public MessagePack repository and the source of the four review branches.
- `Zaelot/Junction2016OfficeEfficiency` - an unrelated historical Tieto/Junction project.
- `mfmatozza/tieto-junction` - this project's private repository.

GitHub does not expose other teams' private repositories or their names. Public search can only reveal public repositories and public metadata, so no claim is made about private teams.

## Differentiation

Do not compete on "AI reviews code" alone. Vouch's visible difference is:

1. feedback from real users or requirements;
2. mechanically checked evidence;
3. risk-based reading list;
4. named human sign-off;
5. trust that rises after clean merges and falls after escaped bugs;
6. Aiven PostgreSQL + Kafka as the auditable data layer.
